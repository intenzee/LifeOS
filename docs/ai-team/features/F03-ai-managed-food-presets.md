# F03 — AI-Managed Food Presets ("Say it once")

| | |
|---|---|
| **Phase** | 1 |
| **Owner** | AI Engineer A ("Food") |

| **Depends on** | F02, SwiftData `FoodPreset` (C1), F09 for reminders (Phase 4) |

## 1. Problem
People eat the same handful of meals most days. LifeOS only has flat single-item lists (`recentFoods`, `favoriteFoods`, `customFoods`). There is no way to say "my usual breakfast", and nothing learns routines.

## 2. Outcome
- The user can **create** a preset by saying it: *"Save this as my usual breakfast"*, *"Remember 'gym shake' is 1 scoop whey, 300 ml milk and a banana."*
- The user can **use** it by name in any channel: *"log gym shake"*, Siri, Watch tap, widget.
- The AI **maintains** presets: suggests new ones from repeated meals, merges duplicates, keeps macros in sync, handles variants ("usual breakfast but no sugar"), archives stale ones.
- Optional **routine automation**: per-preset reminders or auto-log with undo (opt-in).

## 3. Data model

```swift
@Model final class FoodPreset {
    var id: UUID
    var name: String                         // "Usual breakfast"
    var aliases: [String]                    // ["my usual", "morning usual", "nashta"]
    var items: [PresetItem]                  // name, qty, unit, grams?, kcal, P/C/F, nutritionSourceRef
    var defaultMealType: String?
    var typicalWindow: TimeWindow?           // learned, e.g. 07:30–09:00 weekdays
    var typicalWeekdays: [Int]               // 1…7
    var source: PresetSource                 // .user, .aiSuggested(acceptedAt), .imported
    var usageCount: Int
    var lastUsedAt: Date?
    var autoLogPolicy: AutoLogPolicy         // .off (default), .remind, .autoLogWithUndo
    var archived: Bool
    var embedding: Data?                     // NLContextualEmbedding of name+aliases+items
    var totals: Macros { items.sum }         // derived
}
enum AutoLogPolicy: String, Codable { case off, remind, autoLogWithUndo }
```

## 4. Capabilities

### 4.1 Create
| Path | How |
|---|---|
| From a confirmation card | "Save as preset" button → T1 suggests a name (`preset.name.v1`) the user can edit |
| By voice/text definition | F02 parse with intent `definePreset` → items resolved by Nutrition Resolver → confirm card |
| From a day's meal | Long-press meal section → "Save as preset" |
| From AI suggestion | §4.3 |

### 4.2 Use — preset resolution
Input phrase (from F02 `presetPhrase`, Siri parameter, or chat) → candidates:
1. Exact alias/name match (case/diacritic-insensitive).
2. Fuzzy (Levenshtein ≤ 2 on normalised tokens).
3. Semantic: cosine similarity of on-device embeddings ≥ 0.80.
4. Time prior: boost presets whose `typicalWindow` contains *now*.

If the top candidate leads by a clear margin → use it; else show a 2–3 option picker. "My usual" with no name → highest-scoring preset for the current window.

### 4.3 Suggest (routine mining, T0)
Nightly (BG processing task, or on app open if overdue):
- Represent each logged meal as a set of normalised food IDs (+ coarse quantities).
- Find itemsets that occur ≥ 3 times in 14 days (or ≥ 4 times in 30) with Jaccard ≥ 0.8 between occurrences.
- Exclude sets already covered by a preset.
- Rank by frequency × recency; propose at most **1 suggestion per day**, as an in-app card (not a notification): *"You've had poha + chai most weekdays this fortnight. Save it as 'Weekday breakfast'?"*
- Name generated by T1, editable.

### 4.4 Maintain (AI housekeeping, weekly)
| Job | Rule |
|---|---|
| Merge duplicates | Two presets with item Jaccard ≥ 0.9 → suggest merge (never auto-merge) |
| Drift | If the user edits a preset's items in ≥ 3 of the last 5 uses the same way → suggest updating the preset |
| Stale | Not used in 60 days → move to "Archived" (reversible), notify in the presets screen only |
| Nutrition sync | If a referenced custom food or DB value changes → recompute totals, keep a history entry |
| Window learning | Update `typicalWindow`/`typicalWeekdays` from usage timestamps (median ± IQR) |

### 4.5 Variants
*"Usual breakfast but no sugar and 2 eggs instead of 1"* → load preset → T1 parses modifiers into a diff (`remove`, `replace`, `changeQuantity`, `add`) → apply deterministically → confirmation card shows the diff highlighted. Variant is logged; preset unchanged unless the user taps "Update preset".

```swift
@Generable struct PresetModification {
    var operations: [PresetOp]     // op: add|remove|replace|setQuantity, target, newItemText, quantity, unit
}
```

### 4.6 Routine automation (with F09)
- `remind`: at the start of `typicalWindow`, an actionable notification "Log usual breakfast? (420 kcal)" with **Log** / **Something else** actions — logs without opening the app.
- `autoLogWithUndo`: at the end of the window, if nothing has been logged for that meal, log the preset and send a quiet notification with **Undo**. Only for presets used ≥ 10 times, only after explicit opt-in per preset, and auto-disabled after 2 undos in a week.

## 5. Watch & widgets
- `presetsDigest` (contracts C4) syncs the top 8 presets to the Watch for one-tap logging.
- Interactive widget (iOS 17+) with 3 time-relevant presets.

## 6. Edge cases
- Two presets with the same alias → disambiguation sheet; prompt user to rename.
- Preset includes an item with an LLM-estimate nutrition source → badge the preset "contains estimates".
- User deletes a custom food used in presets → keep a frozen copy inside the preset.
- Travel / timezone change → windows are in local time; suspend auto-log for 48 h after a timezone change.

## 7. Acceptance criteria
- [ ] Preset resolution top-1 accuracy ≥ 95% on a 200-phrase golden set across 20 synthetic users' preset libraries.
- [ ] Mining finds ≥ 90% of planted routines in synthetic 60-day logs with ≤ 1 false suggestion per 30 days.
- [ ] No auto-log ever occurs without explicit per-preset opt-in (unit + UI test).
- [ ] Every auto-log is undoable from the notification and from the day view.
